# 保存データと処理の役割を決める質問

## 決定済みの内容

本人がPC・スマホで同じ保存データを使う、1企業に複数メモ、手入力とOCR生成、元画像の永続保存なし、企業ごと1参照メモで比較する方針を引き継ぐ。保存8状態・通常6状態・終了企業の再表示、検討中の集計除外、次の選考日の強調も再承認済み。古い上書きの検出と、削除確認後の変更による停止・最新取得・再確認は変更しない。

一般向け会員募集・共有・移行・カレンダー同期・本文の自動構造化・新DBと復習の接続は追加しない。無料枠を第一条件とし、課金・契約・外部サービス設定をこの回答で実行しない。

## 設計の進め方

内部の役割は次の6つを基本案として、責任・データの所有者・呼出関係を設計する。製品機能を増やしたり、6つの別リリースへ分けたりする意味ではない。構成の代替案と選択理由は設計書でレビュー・承認する。

| 役割の案 | 責任と保存データの境界 |
|---|---|
| 本人確認とアクセス制御 | 本人の識別と利用可否。DB・認証サービスは依存先として別途選定 |
| 企業・メモ管理 | 企業ID、所属メモ、状態、日付、保存版、削除と同じ操作の再試行を一貫して扱う唯一の書込元 |
| OCR・メモ生成 | 元画像の一時処理、訂正OCRと検証した生成結果。保存確定は企業・メモ管理へ渡す |
| 企業比較 | 保存済み企業・選択メモを読み、比較を作る。企業・メモを直接複製・書換えしない |
| 既存の面接前復習 | 既存の生成結果から復習を作る。新しい保存メモとの連携は今回追加しない |
| 画面と編集・出力 | ボード・詳細・編集・未保存入力・情報区分・対応するMarkdown出力 |

今回の成果物は役割とデータの所有者・項目名までを扱う。詳しい保存形式・API・検証コマンド、サービスの選定・無料枠調査、費用と応答時間の確認条件は後続の設計・実装計画で具体化し、実装前の確認に含める。未調査の無料枠や性能を達成済みとしない。

## Q1. 企業詳細の志望度と、比較で使う志望度・理由はどう扱いますか？

企業詳細に志望度があり、既存比較にはメモごとの志望度・理由があります。同じ企業の参照メモを切り替えた時に何を表示するかが未決定なので、値の保存先と編集の影響を確認します。「自分の企業メモ」と比較用の理由は別に扱い、どちらも本人の記入です。

- A. 志望度は企業ごとに1つにする（推奨）。企業詳細と比較は同じ企業の志望度を表示・編集し、参照メモを変えても志望度は変わらない。比較の理由は選んだメモごとのコメントとして保存・編集し、参照メモの切替でそのメモの理由へ変わる。企業の自由記入メモは独立したまま。
- B. 企業詳細の志望度と、メモごとの比較用志望度・理由を別々に保存する。画面で参照元を明記し自動同期しない。参照メモを切り替えると、比較用志望度と理由はそのメモの値へ変わる。

## Q2. 画像のOCR・生成・Web補足・既存復習も、本人のログインを必要にしますか？

保存企業・メモ・新しい比較には本人確認が必須です。一方、現行の生成APIは未認証で呼べるため、既存機能との境界を決めます。どちらの案でも保存データを公開せず、既存の生成・復習・Markdown出力の利用導線は保持します。`/api/health` は公開確認用のままです。

- A. 既存のOCR・生成・Web補足・復習も本人のログイン後に使う（推奨）。個人用の入口と外部API利用を同じ本人確認で守る。未ログイン時はログインへ案内する。
- B. 既存のOCR・生成・Web補足・復習はログインなしの入口を残す。企業への保存や新しい比較に進むときだけログインする。公開生成の費用・呼出制限と保護方法は後続設計で別に確認する。

## Q3. 保存量の設計・検証に使う代表データは、どの規模にしますか？

対応中15社という警告は、保存企業数・メモ数の上限ではありません。無料枠の容量と、ボード・メモ取得・比較の確認条件を見積もるため、架空データの規模を決めます。選んだ件数で登録を禁止したり、実際のデータを提供してもらったりする意味ではありません。応答時間の目標・測定条件・実際のサービス上限は後続の計画で別に確認します。

- A. 企業100社、メモ合計1,000件、長い本文の例は1メモ約10,000字（推奨）。1社に50件所属する例も含め、残りを他社へ分ける。
- B. より多い規模を確認したい。企業数・メモ合計・長い本文の目安を回答に追記する。
- C. より小さい規模で始めたい。企業数・メモ合計・長い本文の目安を回答に追記する。
