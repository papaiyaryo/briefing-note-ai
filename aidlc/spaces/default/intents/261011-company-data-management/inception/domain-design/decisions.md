# 構成と所有者の設計判断

各判断はDomain Designの提案であり、この成果物の承認を待つ。Q1〜Q3の実回答を内容の根拠にする。実装開始・外部サービスの契約・設定の承認ではない。

## ADR-001 — 企業と所属メモの保存正本を一つの管理役割へ置く

### Context
企業IDと複数メモ、状態と社数、確認後のメモ変更を含む企業削除、二重送信・古い更新を一貫させる必要がある。現行はブラウザ保存で企業モデルと所有者がない。

### Decision
CompanyWorkspaceをCompany・Memo・WriteOperation・DeletionSnapshotの唯一の所有者とする。生成候補、比較結果、未保存入力は別の一時的な責任へ分ける。具体的なストアと原子的な処理方法は後続の契約・詳細設計で定める。

### Consequences
企業削除と所属変更の整合性を一つの責任で検証できる。管理役割は大きくなるが内部の読取・書込やリポジトリの分割は後で可能。CompanyWorkspaceを経由しない別の保存経路を作らない。所有者識別・削除対象の版検査・部分変更防止をサーバーで実現する責任が明確になる。

### Alternatives Rejected
企業とメモを別管理役割へ分ける案は、削除と子集合の更新に跨る調整が増えるため今回では採用しない。生成・保存・比較を同じ機能へまとめる案は、外部出力と保存正本・本人入力の境界が弱くなるため採用しない。配置方式や別サービス数の判断はここでは行わない。

## ADR-002 — 志望度は企業正本、比較理由は参照メモの本人コメント

### Context
企業詳細と従来比較の両方に志望度がある。比較に使うメモを切り替えた時の値と理由の保存元が未決定だった。

### Decision
Q1 Aに従い、志望度はCompany.interestLevelを企業詳細と新比較で共通参照・編集する。理由はMemo.comparisonReasonで選択メモ単位に保存する。企業自由メモ・説明会事実・構造化項目とは区別する。

### Consequences
メモを切り替えても企業志望度は変わらず、理由と7観点は選択メモへ切り替わる。更新・競合はCompanyWorkspaceが扱う。旧localStorageの志望度と理由は別正本のままで、自動同期・移行しない。本人コメントを会社の確定事実として扱わない。

### Alternatives Rejected
企業と比較メモで志望度も別に持つ案はQ1 Bであり、本人はAを選んだ。比較理由を企業の自由メモと同じ項目へ上書きする案は、企業全体の記入と個別メモの理由が混ざるため採用しない。メモ切替時の値のコピーも正本を増やすため行わない。

## ADR-003 — 既存生成・復習を含む本人確認を共通の境界とする

### Context
サーバー保存は本人のみ、現行OCR等のAPIは未認証。既存機能を保持しつつ新保存と外部処理の利用境界を定める必要がある。

### Decision
Q2 Aに従い、既存OCR・構造化生成・Web補足・復習と新保存・新比較は本人ログイン後に利用する。各処理のサーバー側はAccessControlで本人を確認し、保存対象はCompanyWorkspaceで所有権を照合する。ログイン入口・公開healthは区別する。

### Consequences
既存機能の利用導線はログイン後へ変わる。秘密情報と認証設定はサーバー側で扱い、UIの非表示だけでは保護の代わりにしない。未認証の直接要求、失効、ログアウト後の遅延応答を検証する必要がある。認証製品・セッション・設定値は後続の計画で選定する。

### Alternatives Rejected
生成だけ未認証の入口を維持する案はQ2 Bであり、本人はAを選んだ。認証検査をUIだけに置く案は直接API要求を防げないため採用しない。一般会員募集・共有権限を同時に追加する案は承認範囲外。

## ADR-004 — 比較は選択した保存正本の派生結果として扱う

### Context
手編集本文と構造化データは別正本。新比較は本人のサーバー保存メモを使い、旧ブラウザデータを自動移行しない。既存復習には新DB接続を追加しない。

### Decision
CompanyComparisonはCompanyWorkspaceから参照データを取得し、企業・メモ・保存版を明示して一時比較を作る。表示とMarkdown出力は同じ参照内容から作り、参照の変更・削除・取得失敗は古い結果を最新として出力しない。InterviewReviewは既存生成結果からの導線を保持する。

### Consequences
比較だけが持つ新しい企業・メモの複製正本を作らない。欠損情報・本人印象・紙由来事実・Web出典の区別を維持できる。最新取得と結果無効化の確認が必要。比較結果の永続化・自動統合・本文の自動構造化は追加しない。

### Alternatives Rejected
比較用に企業とメモを複製保存する案は正本の食違いが増えるため採用しない。旧localStorageから企業IDを推定して移行する案は範囲外。本文からLLMで比較項目を再生成する案も今回の確認済み方針に合わない。

## Security and Data Boundaries

企業・メモの内容は本人の対象だけを返し、外部API秘密情報・画像・OCR・本文を不要に記録しない。未保存候補と保存正本、本人コメントと企業事実、紙由来とWebを区別する。外部OCR側の保持条件はアプリの画像非保存と別に調査する。具体的な所有者制約、権限確認、完全スキーマ・期限・タイムアウトは後続契約で設計・検証する。

## Remaining Decisions Before Implementation

Q3 aの代表データ量は設計入力として確定したが、無料枠・実容量・通常と初回の応答目標・測定条件は未確定。認証・DB製品、サービス休止時の復旧、正式APIと保存の一貫性、入力上限・再試行、80% line coverageの計測・CI、各検証コマンドと公開確認を後続のInception計画で具体化し、人間が確認してから実装する。今回はこれらの達成や構築を主張しない。
