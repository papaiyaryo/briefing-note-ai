# 企業メモ管理の画面モック

## Purpose and Review
実装前の画面・操作の設計資料。1リリースBoltの範囲を守り、実際の認証・API・保存処理は実装しない。[Q1]〜[Q3]は質問ファイルの実回答A。Classicで省略されたラフ画面を復元・捏造せず、承認済み要件とストーリーから直接作成した。

[画面プレビュー](prototype.html)は外部通信・永続保存なし、架空データだけの単独HTML。画面切替と状態見本を操作できる。カードから開く企業詳細・編集は架空企業Dの固定見本。本文プレビューも固定見本で、入力と自動連動しない。保存・ログイン・削除・ダウンロードの実行成功を証明するものではない。ここにない異常系も操作仕様に記載する。

## Updated Design Basis

利用者の追加希望「次の選考をもっと目立つように表示。検討中もあっていいな。あと不採用と辞退は表示しなくていいかも。」と変更確認Q1の実回答aを受け、再承認されたFR3／FR4・US3.1／US3.2／US4.1へ揃える。次の選考日をカードと企業詳細で大きく表示する。検討中は未応募と別状態、両方とも対応中に含めず、応募済・書類選考・面接だけを数える。不採用・辞退は通常表示から隠し、記録は残して「終了した企業を表示」で参照できる。

保存8状態・通常6状態を現在の設計基準とする。変更前の影響評価と実回答は[変更の影響と確認](board-change-impact.md)に履歴として保持する。本書は変更後の画面設計の承認対象であり、アプリ実装の承認ではない。

## Information Architecture
共通ヘッダー: アプリ名、企業ボード、企業比較、画像からメモ、ログアウト。既存の画像→OCR確認→構造化・Web補足→Markdown編集→復習・出力を維持する。本人のサーバー保存画面は認証を必要とする。既存生成APIの認証適用範囲はDomain Designで決定する。

企業ボード → 企業詳細 → 所属メモ編集。比較は独立画面から各社の参照メモを選ぶ。長文編集は専用ページ。登録は名前だけの小さなダイアログ、任意項目は企業詳細で編集する。破棄・削除確認にもダイアログを用いる。長い編集フォームや重ねたダイアログを作らない。

## Layout Specifications
### S02 — ボード
上部はタイトルと企業追加。次に「対応中8社」「目標5〜15社」。15社以上のみ文字付き警告。0・4・5・14社では警告なし。登録や操作を禁止する上限として使わない。検討中は対応中社数に含めない。

PCは通常6列（未応募・検討中・応募済・書類選考・面接・内定）、終了企業の再表示時は辞退・不採用も加えた8列。各列は見出し＋件数＋カード。幅不足ではボード領域のみ横スクロール可能とし、キーボードと左右移動ボタンで表示列へ到達する。ページ全体に意図しない横溢れを出さない。企業カードには名前、次の選考日、状態、メモ件数と詳細リンク。次の選考日は青緑の独立領域に約25pxの太字と明示ラベルで表示し、状態・メモ件数の12〜14px補助文字より目立たせる。未設定なら文字で示す。メモ件数を社数に代用しない。

スマホはQ2 Aの縦配置を維持し、通常6グループを並べる。上部に表示中の状態への移動リンクを折り返し表示。タップ後は対象見出しへフォーカスし、戻って別状態へ移動できる。空のグループも見出しと0件を残す。不採用・辞退は既定非表示で、終了企業の表示ボタンを押すと2状態と移動リンクを追加する。表示切替で保存データを削除・状態変更せず、対応中社数と警告も変えない。終了企業だけが保存されている場合は「表示対象の企業はありません」と再表示操作を示し、保存企業0件と取り違えない。

### S03 — 企業詳細
名前＋状態の直下に次の選考日の強調領域、その下に企業情報と所属メモ。次の選考日と応募締切は別項目とし、保存した暦日を端末でずらさない。企業名のみ必須。業界・志望度・企業メモ・次の選考日・締切・公式URLは任意と明記。状態は検討中を含む8状態のnative selectと明示保存。未確定の状態は列や社数へ確定反映しない。未応募と検討中は別に扱い、初期状態は未応募のまま。辞退・不採用への変更保存が確定したら結果を文字で示し、ボードでは通常非表示となる旨と終了企業を再表示する操作を案内する。

長い名前は折返し。表示名変更でもメモとの所属を保つ。企業メモは「自分の企業メモ」と表示。志望度の正本関係は要件レビューR-01の未決定事項であり、比較用メモとの自動同期をUIで約束しない。

### S04 — メモ編集
企業への戻りリンク、イベント等の識別情報、保存状態。領域切替「本文」「比較用項目」「原文・出典」を表示し、相互の正本が別であることを短い案内で説明する。切替で入力を破棄しない。
- 本文: PCで編集とプレビューを左右に表示。768px未満は編集／プレビュー切替。
- 比較用項目: 事実・事業・強み・人物像、HR強調、印象・懸念、質問、ES材料、次の調査を区分して編集。既存schemaに対応する繰返し入力。空項目を架空値で埋めない。
- 原文・出典: 訂正OCR、イベント名／日付／登壇者、採用Web補足を別領域へ。WebはURL・取得日。原画像は保存メモで再表示できるとは示さない。
保存と.md出力を別操作にする。未保存本文の出力は「編集中の本文」と示し、保存成功と混同させない。構造化項目の保存で本文を自動書換えしない。

### S05 — OCR確認
保存先企業は生成前から明示し、生成名で変更しない。PCでは一時画像とOCR編集を左右、スマホでは上下に並べ、両方にアクセスできる。画像は拡大可能な表示領域。画像選択後のaltは「選択した説明会メモ画像」など機微な内容を転記しない名称。

OCR確認→生成結果確認は戻って修正できる。生成失敗・不正構造は保存対象にしない。dummy表示は「デモの生成結果」を残す。不要になった画像参照を解放する。外部サービスの保持条件は設計で確認する。

### S06 — 比較
企業チェック選択＋各企業に参照メモ選択。1企業1メモを明示。構造化項目がないメモは理由を示し、本文を自動解析しない。PCでは観点を行・企業を列とする表、スマホでは同じ観点ごとに企業を縦比較する。表示形式は画面幅で適応し、表／ボード切替の新機能ではない。

7つの既存比較観点（強み・懸念・印象・HR強調・人物像・ES材料・質問）を保持する。企業と参照メモを見出しに表示し、欠損は未記載／要確認。Web補足は別領域でURL・取得日。志望度と理由の参照元はDomain Designで決めるまで、モックで保存連動を模擬しない。新サーバー比較と「このブラウザの旧比較」を明示区別し、旧データへ自動移行・削除をしない。

### D02 — 変更後の削除確認
Q3 Aで選択された期待結果:
1. 確認対象と所属メモ件数を表示。取消で変更なし。
2. 確認後に別端末が対象メモを編集／追加／削除した場合、古い確認を使う削除を拒否。新しい削除を自動実行しない。
3. 最新取得成功後、変更があった旨と最新の対象・件数・更新情報を示し、もう一度本人の明示確認を求める。企業削除時は所属メモの変更も検出対象とする。
4. 対象が既に削除済みなら「既に削除されています」と一覧へ戻る導線。別対象の削除に置換しない。
5. 最新取得失敗なら再確認を許可せず、失敗と再取得を表示する。
具体的なversion／子集合検査と削除の一貫した契約はDomain Designで定める。期待結果は人間回答Q3 Aと、再承認済みAC6.4.5／AC6.5.6に一致させる。

### D03 — 企業登録
S02の「企業を追加」で開く。企業名欄へ初期フォーカスし、名前だけで未応募として登録することを示す。取消・Escapeでは登録せず、閉じたら起動ボタンへ戻す。入力済み内容を閉じる場合は破棄を明示確認し、ダイアログを重ねず同じ領域を切り替える。送信中は重複登録を抑え、拒否・結果不明では入力を保持して復旧方法を示す。確定保存後は同じ企業の詳細へ進み、h1へフォーカスする。プレビューは配置の見本だけで登録を行わない。

## Screen States
| 状態 | 見える内容 | 操作／復旧 |
|---|---|---|
| 読込中 | 「読み込んでいます」、領域のプレースホルダー | 結果前に0件と確定しない |
| 空 | 企業0件なら登録、メモ0件なら手入力／画像生成 | 空グループも状態名を保持 |
| 通常表示対象なし | 終了企業だけが保存されている旨、終了企業を表示 | 保存企業0件と区別し、再表示から詳細とメモへ |
| 表示成功 | 本人の保存済みデータ、社数、更新情報 | 保存済み正本を利用 |
| 読込失敗 | 「取得できませんでした」、再取得 | 0件・架空結果・誤った出力を出さない |
| 情報不足 | 任意日付なし、未記載／要確認、構造化項目なし | 理由を示して編集へ |
| 保存中 | 「保存しています」、同じ送信を抑制 | 入力と送信対象を保持 |
| 保存拒否 | 欄別エラーまたは保存失敗、未保存表示 | 前の有効データ＋入力保持、再試行 |
| 結果不明 | 「保存結果を確認できませんでした」 | 再取得で確認、重複作成防止 |
| 更新競合 | 「別の端末で変更されています」 | 入力を保持して最新内容を別表示、自動上書きなし |
| 認証失効 | 再ログイン案内。保護内容を非表示 | 入力の再認証後復帰を設計。保護データを未認証のまま操作しない |
| 削除後変更 | 更新説明＋再確認／既に削除済み | 古い確認で実行しない |

## Responsive Verification Conditions
Q1 A: PC 1366×768、スマホ390×844を主な画面確認例にし、320px・767/768px・200%/400%拡大を境界確認する。テスト機器・ブラウザバージョンは検証計画に実際の条件を記録する。400%拡大時は単一列へ再配置し、二次元表は領域内の操作を提供する。モックの画面確認と本番の受入確認を区別する。
