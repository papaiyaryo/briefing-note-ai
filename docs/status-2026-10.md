## 今後の方針：DB で企業ごとに管理する（Notion ライク）

Google Drive への保存（Phase 7）はやめて、アプリ側でデータベースを持つ方針にする。

**理由**

- Drive に Markdown を置くだけでは、Obsidian で見られる程度の価値しかない
- 企業ごとにまとめて、検索・比較・再利用（ES・面接準備）できる形で管理したい

**イメージ**

```txt
企業
├── 企業情報（業界・志望度・選考ステータスなど）
├── 説明会メモ（複数。イベントごと）
│   ├── 元画像 / OCR テキスト
│   ├── 構造化メモ（事実 / 印象 / HR 強調点 / 質問 / ES 材料）
│   └── 採用した Web 補足（出典付き。紙メモ由来の情報とは分ける）
├── 面接前復習メモ
└── 逆質問・ES 材料の蓄積
```

**検討事項**

- DB の選定（Vercel Postgres / Supabase など）と画像の保存先
- ユーザー認証が必要になる（AGENTS.md では MVP 対象外としていた範囲）
- 現行の `CompanyMemoStructured` と localStorage の比較データを DB モデルへ移行する
- 企業比較・面接前復習を DB 上のデータから生成するように変える
- Phase 7 の Issue（#37〜#40）をクローズするか、方針変更として書き換えるか

## 残課題・後片付け

1. **PR #97 が 2 Issue を同時に実装していた**：`1 Issue = 1 PR` ルール違反で、これが PR #98 のコンフリクトの原因になった。PR #98 は main をマージしてコンフリクトを解消し（差分 0）、マージ済み。Issue #45 / #46 はクローズ済み。
2. **面接前復習の中断処理**：`BriefingNoteFlow` で `AbortController` を作っているが、`requestInterviewReview` に `signal` を渡していない。
3. **Web 補足の設定漏れが見えない**：`WEB_SUPPLEMENT_ENABLED=true` と `OPENAI_WEB_SUPPLEMENT_MODEL` がないと `not_configured` になり、クライアントは黙って 0 件として扱う。
4. **Web 補足のエラーが握りつぶされる**：`handlePrepareWebSupplements` が `try/finally` のみで `catch` がない。タイムアウト等が起きても画面に何も出ないまま、OCR ステップに留まる。
5. **Codex のブランチ名**：`codex/github-mention-phase-9]-es` のように `]` を含み、AGENTS.md の命名ルールに違反している。

## 環境変数メモ

- ローカル：`.env.example` をコピーして `.env.local` を作り、`OPENAI_API_KEY` を設定する。未設定だと全機能が dummy になる
- Web 補足を使う場合は、さらに `WEB_SUPPLEMENT_ENABLED=true` と `OPENAI_WEB_SUPPLEMENT_MODEL` を設定する
- Vercel：環境変数は Production にもチェックを入れる。変更後は Redeploy が必要
- Vercel Firewall：AI Bots を Deny、Bot Protection を Challenge に設定済み
- 公開時は OpenAI ダッシュボードで月の使用上限を設定する。API ルートには認証がない
